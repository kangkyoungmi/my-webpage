## 1. 배경 및 문제 정의

사업부지(태양광·풍력) 검토 요청이 들어올 때마다, 담당자가 토지이음·브이월드 등 여러 사이트를 직접 열어 필지별 지목·면적·용도지역·규제사항·개별공시지가를 조회하고 이를 토지조서 엑셀 양식에 손으로 옮겨 적고 있다. 건당 2~4시간이 소요되며, 그중 조회(2단계)와 옮겨 적기(3단계)가 병목이다. 이 두 단계는 판단이 거의 필요 없는 반복 작업이라 자동화 효과가 크다. 규제사항은 출처 사이트마다 문구가 달라 동일한 규제를 표기만 다르게 안내하는 문제가 있어, 이 부분만 AI로 항목 단위 정리·정규화가 필요하다.

**핵심 원칙**: 조회와 옮겨 적기는 규칙(코드)으로 처리해 값이 임의로 바뀌지 않게 하고, AI는 규제 문구 정리·요약에만 국한한다.

## 2. 목표 및 성공 기준

과제정의서 3단계 기준을 그대로 개발 마일스톤으로 사용한다.

| 단계 | 성공 기준 | 대응 개발 범위 |
| --- | --- | --- |
| MVP (1일차, 9/9) | 지번 1개 입력 → 토지조서 1행이 자동 생성 | Phase 1 |
| 목표 (2일차, 9/16) | 여러 지번을 한 번에 입력 → 일괄 생성, 조회 실패 칸 표시 | Phase 2 |
| 이상 (3일차, 9/23) | 법령·규제 검토 결과가 조서에 함께 붙음 | Phase 3 |

**정량 지표**:
- 부지 1곳(필지 10~70개) 조서 생성 시간: 기존 2~4시간 → 목표 10분 이내(조회 대기시간 포함)
- 손으로 다시 채워야 하는 칸 수를 오류 지표로 기록 (0에 가까울수록 목표 달성)

## 3. 범위 (Scope)

### 3.1 In-Scope
- 지번(또는 주소) 목록을 입력받아 PNU로 변환
- 지목, 면적(㎡/평), 용도지역, 용도지구, 규제사항, 개별공시지가 자동 조회
- 여러 필지 면적 합산 (합계 및 합계 제외 필지 수 표기)
- 조회 실패/누락 필지는 빈 칸이 아니라 **사유와 함께** 표시
- 조회 출처·조회 시각 기록
- 기존 토지조서 양식과 동일한 컬럼 구성으로 엑셀 출력
- (Phase 3) 규제사항 원문을 항목 단위로 나누고, 동일 규제의 서로 다른 표기를 정리 (AI 사용 구간)
- (Phase 3) 조서 비고란 초안 작성 (AI 사용 구간)

### 3.2 Out-of-Scope (비목표)
- 저촉 여부에 대한 법적 판단 (사람의 검토의견 단계로 넘김)
- 소유자·주소·주민등록번호 등 개인정보 조회/저장 (원천적으로 다루지 않음)
- 사업성 분석, 재무 검토
- 실시간 알림/메일 발송 자동화 (이번 범위 밖)
- 웹 UI (MVP~목표 단계는 CLI/스크립트 실행으로 충분. 팀 배포 시점에 필요하면 별도 과제로 분리)

## 5. 용어 정의

| 용어 | 설명 |
| --- | --- |
| PNU | Parcel Number Unit, 19자리 필지고유번호 (10자리 법정동코드 + 1자리 산구분 + 4자리 본번 + 4자리 부번) |
| 지번 | 토지의 번지 (예: `152`, `산6`, `446-1`) |
| 지목 | 토지의 용도 종류 (전·답·대·임야 등) |
| 용도지역/용도지구 | 국토계획법상 토지 이용 제한 구분 (예: 계획관리지역, 농림지역) |
| 조회상태 | `성공` / `실패` / `부분성공` 중 하나. 실패 시 사유 문자열 필수 |

## 6. 기능 요구사항 (Functional Requirements)

### FR-1. 입력 처리
- 입력: 엑셀 파일 (컬럼: `소재지`, `지번`, 선택적으로 `사업종류`)
- 지번 표기 정규화: `산` 접두어, `-` 부번 포함 형식을 모두 허용 (`152`, `산6`, `446-1`)
- 최소 1행, 최대 500행(1개 부지 단위) 지원

### FR-2. PNU 변환
- 브이월드 주소검색 API로 `소재지 + 지번` → PNU, 좌표(x,y) 조회
- 엔드포인트 (검증 완료, 2026.09.09 기준 정상 동작):
  ```
  GET https://api.vworld.kr/req/search
    ?service=search&request=search&version=2.0&crs=epsg:4326
    &type=address&category=parcel&format=json
    &key={VWORLD_KEY}
    &query={URL인코딩("{시도} {시군구} {읍면동} {지번}")}
  ```
- 응답 예시(실제 테스트 결과):
  ```json
  {"response":{"status":"OK","result":{"items":[{
    "id":"1283036023110980011",
    "address":{"parcel":"전남 영광군 염산면 봉남리 1098-11"},
    "point":{"x":"126.344...", "y":"35.208..."}
  }]}}}
  ```
- 실패 시(검색결과 0건): 조회상태=`실패`, 사유=`PNU 조회 실패 - 주소/지번 확인 필요`

### FR-3. 지목·면적·용도지역·개별공시지가 조회
- PNU로 브이월드 국가중점데이터 API(ned) 호출:
  | 항목 | 엔드포인트 |
  | --- | --- |
  | 토지특성정보(지목·면적) | `api.vworld.kr/ned/data/getLandCharacteristics` |
  | 용도지역·용도지구 | `api.vworld.kr/ned/data/getLandUseAttr` |
  | 개별공시지가 | `api.vworld.kr/ned/data/getIndvdLandPriceAttr` |
- ⚠️ **알려진 제약 (2026.09.09 확인)**: 위 `ned` 계열은 브이월드 **운영키 승인**이 있어야 정상 응답하며, 현재 발급된 키(개발키 등급)로는 전부 `INCORRECT_KEY` 오류가 남. 운영키는 신청 후 별도 심사가 필요하고 즉시 발급되지 않음. → **FR-3은 아래 FR-3-Fallback과 함께 구현**해야 MVP가 API 승인 여부와 무관하게 동작함.

### FR-3-Fallback. 면적 조회 대체 경로 (운영키 미승인 상태에서도 동작해야 함)
1. **연속지적도 Shapefile 방식** (국토정보플랫폼 `map.ngii.go.kr` 또는 `data.nsdi.go.kr`에서 내려받은 `LSMD_CONT_LDREG_*` shp): PNU 앞 10자리(법정동코드) + 지번으로 폴리곤 매칭 후 `area()`로 실면적(㎡) 계산. 이번 세션에서 검증됨 (봉남리 사례 109개 중 49개 매칭 성공, 오래된 지적도 스냅샷일 경우 신규 분할 필지는 매칭 실패 가능).
2. **등기부등본 PDF 방식**: 사용자가 발급받은 등기부등본 PDF 표제부의 면적을 직접 추출 (Vision 기반 PDF 읽기). 신뢰도 가장 높음(공부상 최신 데이터). 이번 세션에서 109/109 100% 성공 사례 있음. 다만 사람이 등기부등본을 직접 발급해 업로드해야 하므로 완전 자동화는 아님 — **반자동 경로**로 설계(파일 업로드 시 자동 파싱).
3. 우선순위: **①브이월드 API(운영키 승인 후) > ②등기부등본 업로드(있으면) > ③연속지적도 매칭(최후 수단, 낮은 신뢰도로 표시)**
4. 어떤 경로로 값을 얻었는지 `데이터출처` 컬럼에 반드시 기록 (`VWorld API` / `등기부등본` / `연속지적도(참고용)`)

### FR-4. 용도지역·용도지구·규제사항 조회
- 1차: 브이월드 `getLandUseAttr` (운영키 필요, FR-3과 동일 제약)
- 대체: **토지이용규제정보서비스(LURIS, open.eum.go.kr)** Open API 신청 및 연동 — 이번 세션에서 미검증, **개발 착수 시 최우선 조사 항목**으로 별도 API 키 신청 필요 (리스크 섹션 참조)
- 규제사항 원문은 여러 개 조항이 붙어 나올 수 있음 → 원문을 그대로 `규제사항_원문` 컬럼에 저장 (1차는 가공하지 않음)

### FR-5. 규제사항 정리 (AI, Phase 3)
- `규제사항_원문`을 줄바꿈/구분자 기준으로 항목 단위 분리
- 동일 규제의 이표기(예: "가축사육제한구역" vs "가축사육 제한 구역(전부제한)")를 표준 사전(`규제표준사전.json`, 팀이 점증적으로 채워나가는 매핑 테이블)과 대조해 정리
- 표준 사전에 없는 신규 표현은 LLM(OpenAI API, `.env`에 키 있음)에 "표준 항목명 후보"를 물어보되, **원문은 절대 삭제하지 않고 별도 컬럼(`규제사항_정리`)에 병기** — 원문 손실 방지
- 조서 비고란 초안은 LLM이 생성하되 사람이 검토 전까지 `[AI초안]` 접두어를 붙여 구분

### FR-6. 면적 합산 (여러 필지, Phase 2)
- 같은 부지에 속한 필지들의 면적(㎡/평) 합계 행 추가
- 합계에 포함되지 않은 필지(조회 실패) 개수를 합계 행에 명시: 예) `합계: 12,345㎡ (조회 실패 2필지 제외)`

### FR-7. 실패/누락 처리
- 모든 조회 단계에서 실패 시 해당 셀을 비워두지 않고 `#조회실패: {사유}` 형식으로 표시
- 표준 사유 코드:
  | 코드 | 의미 |
  | --- | --- |
  | `PNU_NOT_FOUND` | 주소/지번으로 PNU를 찾지 못함 |
  | `API_KEY_UNAUTHORIZED` | 브이월드 운영키 미승인 (ned API) |
  | `NO_MATCHING_PARCEL` | 연속지적도/등기부에서도 매칭 실패 |
  | `API_TIMEOUT` | 외부 API 응답 지연/오류 |

### FR-8. 출력
- 컬럼 순서 (과제정의서 확정 순서): `소재지, 지번, 지목, 면적(㎡), 면적(평), 소유구분, 용도지역, 용도지구, 규제사항, 개별공시지가, 조회상태, 데이터출처, 조회시각, 비고`
- 원본 토지조서 양식 파일이 별도로 제공되면 헤더명을 그 양식에 맞춰 매핑 (설정파일로 컬럼 매핑 관리, 하드코딩 금지)
- 출력 파일명: 프로젝트 명명 규칙 준수 `YYYY.MM.DD_토지조서_{부지명}_v버전.xlsx`

### FR-9. 배치 처리 (Phase 2)
- 입력 엑셀에 여러 지번을 넣으면 순차 조회 후 한 번에 결과 생성
- API Rate limit 대응: 요청 간 최소 200ms 딜레이, 429 응답 시 지수 백오프 재시도(최대 3회)

| 이식성 | Python 3.10+ 단일 스크립트로 실행 가능, 팀 내 다른 PC에서도 `.env`만 교체하면 동작 |

## 9. 데이터 모델

```python
@dataclass
class ParcelRecord:
    소재지: str
    지번: str
    pnu: str | None
    지목: str | None
    면적_m2: float | None
    면적_평: float | None
    용도지역: str | None
    용도지구: str | None
    규제사항_원문: str | None
    규제사항_정리: str | None   # Phase 3
    개별공시지가: int | None
    조회상태: Literal["성공", "부분성공", "실패"]
```
